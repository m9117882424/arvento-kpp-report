# Arvento KPP Reports

Набор Python-скриптов для анализа координатных выгрузок Arvento, расчёта въездов/выездов, пробега внутри и снаружи территории, а также стоянок по зарегистрированным геозонам.

## Поддерживаемые форматы

Для сводного отчёта `arvento_kpp_report.py` поддерживаются:

- `.xlsx`
- `.xlsm`
- `.csv`

XML пока не поддерживается.

Парсер не предполагает, что заголовки таблицы находятся в первой строке. Он последовательно ищет строку, содержащую обязательные колонки: госномер, дату/время, широту и долготу. Поэтому перед таблицей могут находиться одна, две или больше служебных строк, например название отчёта и период выгрузки.

CSV-парсер автоматически:

- определяет разделитель `;`, `,`, табуляцию или `|`;
- проверяет кодировки UTF-8 BOM, UTF-8, Windows-1251 и Windows-1254;
- ищет фактическую строку заголовков после служебных строк;
- обрабатывает десятичную запятую;
- читает файл построчно, не загружая весь CSV в оперативную память.

Excel-парсер также пропускает служебные строки перед таблицей и начинает импорт только после обнаружения фактической строки заголовков.

## Обработка больших файлов

Для крупных выгрузок данные импортируются во временную SQLite-базу.

Порядок обработки:

1. Исходный CSV или Excel читается последовательно.
2. Координатные записи пакетами записываются во временную SQLite-базу.
3. Создаётся индекс по дате, государственному номеру и времени.
4. Анализ выполняется отдельно по каждой дате и каждому автомобилю.
5. В оперативной памяти находится только текущий трек автомобиля, а не весь исходный файл.
6. После успешного завершения временная база удаляется автоматически.

Во время выполнения отображается прогресс:

```text
Импортировано в SQLite: 500 000
Импортировано в SQLite: 1 000 000
Создание индекса SQLite...
Анализ 21.07.2026: автомобилей 95
```

Для исходника размером около 600 МБ рекомендуется иметь не менее 2–3 ГБ свободного места на системном диске, поскольку временная база создаётся в каталоге `%TEMP%`.

## Реестр геозон

КПП и геозоны задаются в `geozones.json`, а не берутся из Arvento.

Раздел `gates` содержит линии КПП. Раздел `geozones` поддерживает:

- `polygon` — полигон;
- `circle` — круг.

Стоянка определяется как интервал более 10 минут между последовательными сообщениями движения. Геозона стоянки определяется по координатам до и после интервала:

- обе точки в одной геозоне — высокая достоверность;
- только одна точка в геозоне — средняя достоверность;
- обе точки вне реестра — `Вне зарегистрированных геозон`.

## Разнарядки

Скрипт автоматически ищет Excel-разнарядки (`.xlsx`, `.xlsm`, `.xls`) в папке исходной выгрузки.

Из разнарядки подставляются:

- водитель;
- грейд;
- должность;
- дирекция.

Дата разнарядки определяется:

1. из имени файла, например `20.07.2026 SON GÜNCEL KİRALIK ARAÇ LİSTESİ.xlsx`;
2. если даты в имени нет — из первых пяти строк книги.

Для каждого листа дневного отчёта выбирается:

1. разнарядка с точной датой отчёта;
2. если точной даты нет — последняя разнарядка, дата которой не позже даты отчёта;
3. если доступны только более поздние файлы — последняя разнарядка из найденных.

Если разнарядки нет или госномер в ней не найден, ячейки остаются пустыми. В отчёт также выводится столбец `Дата разнарядки`, чтобы было видно, какой файл использован.

Распознаваемые названия колонок включают русские, турецкие и английские варианты: `Гос рег знак / PLAKA`, `Пользователь / KULLANICI / Водитель`, `Грейд / SCALA`, `Должность / GÖREVİ`, `Дирекция / Directorate`.

## Запуск сводного отчёта

С выбором исходного файла через диалог:

```powershell
python arvento_kpp_report.py
```

С явным указанием файла:

```powershell
python arvento_kpp_report.py "C:\Reports\Report.csv"
```

Файл `geozones.json` ищется сначала рядом с исходной выгрузкой, затем в каталоге программы. Разнарядки ищутся рядом с исходной выгрузкой.

## Результаты

Для исходного файла `Report.csv` создаются две книги рядом с исходником:

```text
Report_по_дням.xlsx
Report_итоговая_сводка.xlsx
```

### Книга по дням

Каждая календарная дата размещается на отдельном листе: `21.07.2026`, `22.07.2026` и т. д.

Для каждой машины дополнительно выводятся:

- время первого въезда на площадку за день;
- время последнего выезда с площадки за день;
- водитель;
- грейд;
- должность;
- дирекция;
- дата использованной разнарядки.

Если въезда или выезда за день не было, соответствующая ячейка остаётся пустой.

### Итоговая книга

Содержит листы:

- `Сводка по автомобилям` — показатели за весь период;
- `Сводка по дням` — показатели по автомобилю и дате;
- `Стоянки` — детализация всех интервалов стоянок;
- `Стоянки по геозонам` — количество и суммарное время по автомобилю и геозоне.

## Показатели сводного отчёта

- первый въезд и последний выезд;
- водитель, грейд, должность и дирекция;
- начало и конец периода;
- состояние в начале и конце;
- количество въездов и выездов;
- пробег внутри, снаружи и общий;
- процент пробега внутри и снаружи;
- время на территории;
- время движения на территории;
- время стоянки на территории;
- количество стоянок;
- процент движения и стоянки.

## Отчёт по первому въезду

Для рабочего варианта отчёта используйте:

```powershell
python arvento_first_entry_report_fixed.py
```

Или с явным указанием файлов и фильтра времени:

```powershell
python arvento_first_entry_report_fixed.py "Report_24.xlsx" "Разнарядка.xlsx" "Первый въезд.xlsx" --time-from 07:00 --time-to 09:00
```

`arvento_first_entry_report_fixed.py` использует устойчивое определение стороны линии КПП. GPS-точки, расположенные ближе `MIN_SIDE_DISTANCE_M` к линии ворот, считаются пограничными и не сбрасывают последнюю подтверждённую сторону автомобиля.

Например, последовательность расстояний до линии:

```text
+34,2 м → −0,56 м → −8,68 м
```

корректно определяется как одно пересечение. Это устраняет пропуск въезда `34KBF723` около 07:42:57 через КПП 4.

Фильтры по грейдам учитывают только числовую часть значения: `7`, `7A` и `7b` считаются грейдом 7. Параметр `--consider-previous-exits` исключает въезд, если в тот же день до него был зафиксирован выезд через КПП.
