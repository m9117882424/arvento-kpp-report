# Рейтинг эффективности транспорта

## Назначение

Отдельная страница **«Эффективность ТС»** внутри действующего портала Arvento:

- UI: `GET /efficiency`;
- справочники: `GET /api/efficiency/options?date_from=YYYY-MM-DD&date_to=YYYY-MM-DD&latest_roster_only=false`;
- запуск фонового расчёта: `POST /api/efficiency/jobs` с JSON-параметрами;
- статус, результат и Excel: `GET /api/efficiency/jobs/{id}`,
  `GET /api/efficiency/jobs/{id}/result`, `GET /api/efficiency/jobs/{id}/excel`.

Период ограничен **31 календарным днём** для защиты основного PostgreSQL от тяжёлых запросов. Одновременно выполняется не более одного GPS-анализа; ещё один может ожидать. Готовый результат и Excel живут в памяти процесса 30 минут, не записываются в базу. При перезапуске портала расчёт надо запустить заново.

Чтобы повторный выбор госномеров, дирекций, пользователей или моделей не запускал повторное чтение GPS, для **закрытых суток** действует отдельный процессный LRU-кэш суточных GPS-метрик (не более 10 000 ТС-суток, TTL 60 минут). Ключ включает день, номер, контрольные метки сводного кэша, версии геозон, обеденные окна, стоянку и параметры скорости. При изменении этих параметров, источников или геозон соответствующий агрегат рассчитывается заново. **Текущий день не кэшируется**, потому что поступают новые GPS-точки. Для идентичного завершённого запроса готовый результат переиспользуется.

Дополнительно работает **постоянный PostgreSQL-кэш** `efficiency_gps_metric_variants` (миграция `006`, с безопасным переносом записей из исходной таблицы миграции `004`): хранит JSON-агрегат ТС-сутки, не сырые GPS-точки. В SHA-256-ключ входят исходные метки, все значимые настраиваемые параметры, версии геозон и версия алгоритма `efficiency-gps-daily-v1`. После перезапуска портала и при изменении фильтров результат переиспользуется; при изменении скорости, стоянок, геозон или GPS-источников ключ меняется. Для текущих/просроченных суток запись и чтение постоянного агрегата запрещены. Ошибка таблицы или подключения к постоянному кэшу не делает отчёт недоступным: результат пересчитывается по исходным GPS.

На диске сохраняются **разные варианты настроек для одной машины и суток**: новый порог, настройка или версия геозоны не стирают прежний агрегат. При возвращении к предыдущим настройкам GPS-точки повторно не анализируются, если метки исходных данных и алгоритм не изменились. Исходная таблица `efficiency_gps_daily_metrics` оставлена без изменений для безопасного отката. Размер нового кэша зависит от числа реально запрошенных комбинаций; автоматического удаления записей пока нет — требуется мониторинг размера и отдельное согласование ретенции. В `coverage` доступны `gps_metric_cache_hits` (все попадания), `gps_metric_cache_misses`, а также `gps_metric_persisted_hits` и `gps_metric_persisted_writes`. Для аварийного выключения постоянного слоя используется `EFFICIENCY_PERSIST_METRIC_CACHE=0` в окружении портала/фонового задания; без него отчёт выполняется по исходным GPS.

При формировании в интерфейсе видны **текущий этап**, количество обработанных дней, ТС-суток из кэша и заново проанализированных ТС-суток. Счётчик GPS обновляется после завершения каждого календарного дня, поэтому внутри большого дня может временно не меняться. Синхронизация GPS больше не запрашивает `ALTER TABLE` для уже существующего поля `region_name` и не выполняет `CREATE TABLE PARTITION` / `CREATE INDEX` для существующих разделов/индексов: это исключает лишние DDL-блокировки основной таблицы во время долгого чтения отчёта.

Тяжёлая проверка водяных знаков источников на *полностью актуальном закрытом диапазоне* переиспользуется не более **60 секунд**. Для сегодняшнего дня и для устаревшего сводного кэша она вызывается каждый раз; в течение этих 60 секунд поздно пришедшие данные закрытого периода могут ещё не отразиться в рейтинге. После истечения TTL свежесть проверяется заново.

По замеру на PRIMARY 07.11.2026 один холодный день (06.11, 206 автомобилей) занял **31,8 секунды**. Значит, первый месячный отчёт без прогрева может занимать много минут. Постоянный кэш ускоряет **только уже рассчитанные комбинации параметров**. Для холодной истории предусмотрен отдельный контролируемый прогрев; до релиза обязательны замеры 1/7/30 суток, оценка объёма JSONB и независимое ревью. Время месячного первого расчёта пока не объявлено решённым.

### Контролируемый прогрев GPS-кэша

`efficiency_cache_worker.py` выполняет готовый расчёт с настройками по умолчанию для завершённых суток **только после успешной подготовки и проверки свежести** `consolidated_report_cache`. Доступны `--date YYYY-MM-DD` (последний день, по умолчанию вчера) и `--days 1..7`; на неполные сутки выводится `SKIPPED_STALE_CONSOLIDATED_CACHE`, исходные данные не изменяются. Команда для отдельного контейнера после установки миграции:

```bash
docker compose --project-directory /opt/arvento_report \
  -f /opt/arvento_report/docker-compose.server.yml \
  run --rm --no-deps report-portal \
  python efficiency_cache_worker.py --days 2
```

Для отдельного ночного задания предусмотрены `deploy/arvento-efficiency-cache-warmup.sh` и `deploy/systemd/arvento-efficiency-cache.{service,timer}`. Таймер запланирован на **04:40 Europe/Istanbul**, пропускает запуск при занятом `/run/arvento-sync-and-cache.lock`, ограничен по времени и использует низкий приоритет CPU/IO. Пропущенный из-за перезагрузки запуск **не догоняется в рабочее время** (`Persistent=false`); следующей ночью предусмотрен прогрев последних двух суток. **Установщик таймер не включает автоматически**: после контроля релиза оператор должен отдельно выполнить `systemctl enable --now arvento-efficiency-cache.timer`. До включения нужны подтверждение свободного места, время выполнения и отсутствие наложения с ночным кэшем/резервным копированием. Для первой 30-дневной истории используйте последовательные ручные прогревы максимум по 7 суток, только в согласованное окно и после контроля нагрузки.

Портал наследует существующий защищённый путь Nginx; прямой доступ к порту приложения извне не предусмотрен. Старый пункт «Эффективность легкового транспорта» сохранён и не изменяет свой формат.

### Рисование и доступ к геозонам

Только пользователь BDD **`maksim`** открывает [редактор геозон](https://bdd.equippulse.com/geozones/) по своему обычному паролю. Пункт «Геозоны» в левом меню `/efficiency` виден только ему. Другим пользователям доступ к маршруту `/geozones/` и ко всем вложенным API запрещён отдельным Nginx Basic Auth файлом. Права нельзя получить, просто зная URL или скрыв/показав пункт меню. Перед первым использованием устанавливается `deploy/install-bdd-geozones.sh`; после смены пароля `maksim` его необходимо повторить. Не публикуйте порт `18083` наружу.

1. Откройте редактор и переключитесь на карту OSM либо спутниковую карту Google (если задан ключ).
2. Нажмите на карте инструмент **полигон** (для территории, офиса, стоянки, тоннеля) или **линия/точка** для соответствующего контрольного объекта. Кликайте по углам зоны; завершите полигон нажатием на первую точку.
3. Заполните **Код** (уникальный, например `OFFICE_MAIN`), **Название** и **Назначение геозоны**. Назначение описывает объект — офис (`OFFICE`), парковка (`PARKING`), рабочая зона (`WORK_ZONE`), тоннель (`SPEED_EXCLUSION`) и т. д. Оно не ограничивает количество проверок, включённых для одного полигона.
4. В группе **«Какие проверки включены»** независимо отметьте нужное:
   - **Учитывать стоянки** — этот полигон по умолчанию выбирается в перечне офисных стоянок отчёта (даже если его назначение не `OFFICE` / `PARKING` / `WORK_ZONE`).
   - **Разрешённая территория** — этот же полигон по умолчанию включается в перечень разрешённых зон движения.
   - **Контроль скорости** — `Общий порог` (наследуется порог отчёта), `Не фиксировать превышения` (тоннель/помехи GPS) либо `Собственный порог` в диапазоне 5–250 км/ч. При пересечении нескольких зон применяется самый строгий собственный порог; исключение скорости имеет приоритет. Собственный порог применяется в **отчёте эффективности**, а исключения учитываются также в региональном отчёте скорости.
5. Нажмите **«Сохранить»**. Настройки сохраняются вместе с геозоной; изменение создаёт новую версию геометрии для инвалидации кэша расчётов без уничтожения истории.
6. Для редактирования сначала выберите зону из списка; для отключения — **«Отключить»**. Не отключайте `SITE` без предварительной проверки: это основная граница Аккую.

Геозоны с включёнными проверками стоянок / разрешённого движения **автоматически отмечаются при первом открытии** отчёта эффективности. Их можно вручную добавить или убрать для отдельного расчёта без изменения постоянных настроек. Если проверки не включены ни у одной зоны, соответствующие поля остаются пустыми и компоненты рейтинга предварительными. Существующие `SPEED_EXCLUSION` мигрируют в режим исключения скорости; старые офисные зоны остаются доступны для ручного выбора.

## Источники и определения

1. **Сводный отчёт:** `consolidated_report_cache`. Пробег внутри/снаружи берётся из готового кэша, не пересчитывается по GPS при открытии страницы.
2. **Разнарядка:** актуальная на конкретный день запись из `consolidated_roster_snapshots` / `consolidated_roster_entries`. День считается плановым только для машины из разнарядки и только с понедельника по пятницу. В выборку включаются и машины с нулевыми показателями.
3. **GPS:** `gps_points` по нормализованному госномеру за каждый день в `Europe/Istanbul`. Здесь рассчитываются движение внутри площадки, длительность стоянок, переходы через границу, внешние поездки и подтверждённые превышения.
4. **Граница Аккую:** действующий полигон `SITE` PostGIS. Он используется **всегда**, даже если дополнительные зоны пока не нарисованы.
5. **Офисные стоянки:** выбранные полигоны `OFFICE`, `PARKING`, `WORK_ZONE` либо других типов с включённой проверкой стоянок. Включённые зоны предлагаются автоматически. Если ни одна не выбрана, длительность стоянок не рассчитывается и соответствующий компонент рейтинга отключён.
6. **Разрешённые зоны:** выбранные активные полигоны PostGIS, по умолчанию с включённой проверкой разрешённого движения. Если список пуст, использование вне выбранных зон не рассчитывается и не влияет на рейтинг.
7. **Выходные:** суббота и воскресенье. Работа на площадке подтверждается хотя бы одним интервалом движения внутри полигона в такой день, не одним фактом входа в геозону.

### Интервалы GPS

- Движение — две последовательные точки внутри `SITE`, обе со скоростью свыше 3 км/ч и интервалом не более 5 минут.
- Стоянка у выбранного офиса — непрерывная серия точек внутри зоны со скоростью от 0 до 3 км/ч. Полная продолжительность засчитывается **строго при превышении** заданного минимума (по умолчанию более 5 минут). Разрыв между соседними GPS-точками свыше 15 минут завершает серию без домысливания времени.
- Внешние поездки — подтверждённое время движения и ориентировочный пробег Arvento `distance_km` для точек вне всех выбранных разрешённых зон. Некорректные/слишком большие приращения отбрасываются. Пробег вне зон — оценка по GPS, а не бухгалтерский показатель.
- Обед — отдельные счётчики выхода из `SITE` и повторного входа в заданные окна. Учитываются только переходы с подтверждённым GPS-интервалом не длиннее 5 минут: после длительного обрыва связи пересечение не выдумывается. Их наличие/отсутствие **не штрафуется автоматически**.

### Скорость

- Пороги по умолчанию — **50 км/ч внутри** и **103 км/ч снаружи**. Пользователь может изменить оба порога.
- Минимальная продолжительность по умолчанию — **3 секунды**, но в любом случае необходимы **не менее трёх** последовательных скоростных GPS-точек.
- Используется действующая защита от одиночных скачков и физически неправдоподобного ускорения.
- При миграции действующие `SPEED_EXCLUSION` / `TUNNEL` сохраняют режим **«Не фиксировать превышения»**. Затем режим можно изменить независимо от назначения: исключение в любом полигоне прерывает скоростной эпизод, а собственный порог применяется в его пределах. Классификация на площадке / снаружи — по текущему полигону `SITE`.
- Выводятся количество подтверждённых событий внутри и снаружи, интервал, максимум скорости, порог и ссылка на координаты события.

## Рейтинг

Базовые веса:

| Критерий | Вес | Расчёт |
| --- | ---: | --- |
| Дни с нормой пробега внутри | 50% | Дни `inside_km ≥ норматив` / плановые будни в разнарядке |
| Движение / (движение + офисные стоянки) | 25% | Подтверждённые GPS-минуты |
| Доля внутри Аккую | 15% | `inside_km / (inside_km + outside_km)` |
| Использование в разрешённых зонах | 10% | `1 − min(1, км вне зон / общий км)` |

Норматив по умолчанию: Ford Transit / Ford Transıt (в т.ч. турецкое написание `TRANSİT`) — **50 км/день**, остальные модели — **30 км/день**.

Если офисные/разрешённые зоны ещё не выбраны, соответствующие веса **исключаются** и сумма оставшихся нормируется до 100%. Такой балл явно помечается **предварительным**; отсутствие геозон не считается нулевой эффективностью.

К базовому баллу применяется штраф за подтверждённую скорость: **−3 балла за эпизод, максимум −15**, затем результат ограничивается 0–100. Обед и выходные отображаются отдельно и на балл не влияют.

Если у конкретной машины нет GPS за период, плановых рабочих дней или собственной актуальной строки сводного кэша хотя бы за один запрошенный день, балл — **Н/Д**. Машина остаётся в таблице без места в рейтинге. Неполнота разнарядки/кэша **других** машин (`roster_coverage`) не снимает оценку ТС, у которого есть собственный готовый кэш. Остальные причины устаревания суток (`gps_event`, `gps_received`, `geofence`, `vehicle_distance`, ошибки алгоритма и т. п.) остаются блокирующими для всех. Актуальность сверяется механизмом водяных знаков `load_cache_coverage`, а не только флагом `SUCCESS`. Текущие сутки и дни с неполным охватом разнарядки помечаются предварительными.

**Порядковый номер «№» есть у каждой строки**, включая ТС с оценкой `Н/Д`. Это номер позиции в текущей сортировке, а не обещание места в рейтинге. В Excel отдельно выведено «Место в рейтинге», оно заполняется только для ТС с рассчитанным баллом. Так машины без GPS тоже видны и пронумерованы.

Средний дневной пробег внутри/снаружи вычисляется только по плановым будням в разнарядке. Пробег по субботам/воскресеньям остаётся в суммарных значениях и долях, но не увеличивает среднее значение за рабочий день.

**Среднее время движения внутри Аккую за плановый рабочий день** считается по той же дневной базе: подтверждённые GPS-минуты движения в плановые будни по разнарядке делятся на **все** плановые будни конкретного ТС, в том числе дни с нулевым движением. Движение вне разнарядки и по выходным в среднее не включается, но остаётся в суммарных данных GPS и в листе «По дням». Если GPS не появлялся ни в один плановый будний день, среднее — **Н/Д** (не подменяем отсутствие связи нулём). Если GPS есть лишь в части плановых дней, остальные дни остаются в знаменателе; неполнота связи может занизить среднее.

Карточка **«Среднее время движения внутри Аккую за плановый рабочий день»** показывает взвешенное среднее по автопарку: сумма будних минут движения всех ТС, имевших GPS хотя бы в один плановый будний день, разделённая на общее число плановых автомобиледней этих ТС. Это не среднее арифметическое отдельных машин. В подписи карточки указано количество ТС, вошедших в расчёт.

Два независимых рейтинга — **«ТОП-10 эффективных»** (наибольший балл) и **«ТОП-10 малоэффективных»** (наименьший балл) — показывают до десяти машин каждый. При равенстве баллов порядок определяется госномером. Машины без итогового балла (`Н/Д`) остаются в основной таблице, но не попадают в списки. При числе оценённых машин менее двадцати оба списка могут пересекаться. «Малоэффективный» означает только положение в сравнении, а не установленное нарушение. Оба списка видны в мобильной версии.

### Подписи и цветовые ориентиры

- **«Средний пробег внутри Аккую, км/плановый рабочий день»** — сумма пробега внутри за плановые будни, разделённая на число таких дней; рядом с каждой машиной указан норматив для её модели. **Зелёный** — средний пробег достигает норматива, **красный** — ниже него. Цвет не зависит от числа дней с выполненным нормативом или итогового балла. Для модели, изменившейся в течение периода, дневное выполнение нормы рассчитывается по модели на соответствующий день; рядом со средним показан норматив текущей модели.
- **«Дней с нормативом пробега: выполнено / план»** — отдельный счётчик дней с подтверждённым выполнением суточной нормы. Все дни выполнены — зелёный; выполнено не менее 80%, но не все — жёлтый; меньше 80% — красный. Если GPS нет или плановых дней нет, подсветка нейтральная.
- **«Средний пробег вне Аккую за рабочий день, км»** — пробег вне площадки за будни по разнарядке, разделённый на число таких дней. **Отдельного плана или норматива пробега вне Аккую нет**; значение не оценивается цветом и не сравнивается с внутренним нормативом.
- **«Среднее время движения внутри Аккую за плановый рабочий день»** — подтверждённое GPS-время движения в такие дни, разделённое на их число; нулевые рабочие дни учитываются, выходные не входят. Показатель отображается в часах и минутах и не окрашивается по нормативу: отдельной нормы времени движения нет.
- **«Доля пробега внутри Аккую»** — процент от суммарного пробега за весь период, включая выходные. Зелёный при доле не менее 75%, жёлтый от 50% до 75%, красный менее 50% — это **визуальные ориентиры**, а не самостоятельное нарушение правил.
- **«Доля пробега вне Аккую»** — дополнение к доле пробега внутри Аккую до 100% (например, 95,8% внутри + 4,2% вне = 100%). При нулевом общем пробеге обе доли — «Н/Д». Прежнее отношение `пробег внутри / пробег вне`, которое могло давать тысячи процентов, больше не показывается ни на странице, ни в новом Excel; старое поле `inside_to_outside_percent` пока сохраняется только в JSON API для совместимости.
- **«Доля движения в движении и офисных стоянках»** — подтверждённое время движения внутри / (это время движения + стоянки в выбранных офисных зонах), а не отношение движения к одним стоянкам.
- **«Среднее время движения»** в карточке — на плановый автомобиледень (не общая сумма). **«Суммарное время стоянок»** и **«эпизоды»** — значения по всем включённым машинам за весь выбранный период. «Н/Д» означает невозможность достоверного расчёта; отсутствие настроенных офисных геозон поясняется отдельно.
- Красный цвет у времени офисных стоянок обозначает **больше времени стоянок, чем движения**; это ориентир эффективности, а не юридически установленное нарушение. Подтверждённые превышения скорости — самостоятельные события.

## Фильтры и экспорт

Доступен множественный выбор госномеров, дирекций, пользователей, марок/моделей **и грейдов**, диапазон дат, два обеденных окна, два порога пробега, минимальная стоянка, два порога скорости и длительность, а также два независимых списка геозон. Грейды получаются из поля `grade` **действовавшей на каждую дату центральной разнарядки**, а варианты строятся по выбранному периоду. При сравнении учитывается только числовая часть: `7`, `7a` и `7B` — один грейд `7`; дробные значения поддерживаются. Пустой/нечисловой грейд не попадает в варианты и исключается при включённом фильтре. Множественный выбор объединяет перечисленные грейды; с остальными фильтрами действует пересечение. Выбор применяется ко всем показателям, рейтингу, дневной детализации и Excel; значения фильтра сохраняются на листе «Методика». Без выбора грейда отчёт остаётся прежним. Дополнительной загрузки GPS фильтрация не требует: неизменный дневной GPS-кэш используется для вошедших в выборку ТС.

Чекбокс **«Машины только из свежей разнарядки»** по умолчанию выключен. Если его включить, в таблицу, расчёт и Excel попадают **только** госномера из разнарядки с максимальной датой `roster_day` в `consolidated_roster_snapshots`, независимо от выбранного периода. Варианты госномеров и других фильтров также ограничиваются этим составом; выбранные ранее значения, которых больше нет в перечне, сбрасываются при переключении. Рядом выводятся дата и размер самой новой разнарядки. Этот переключатель **не заменяет исторические разнарядки**: для каждого дня принадлежность к разнарядке, плановые дни, пробеги, стоянки и оценка рассчитываются по данным, действовавшим на эту дату. Поэтому автомобиль, добавленный только после выбранного периода и не имеющий в нём исторических данных, не отображается; автомобиль из новой разнарядки с историческими данными сохраняется даже при нулевом пробеге. При выключенном переключателе действует старая логика без ограничений по текущему составу автопарка. Готовые исторические результаты для этого режима не переиспользуются после нового запуска, чтобы изменения в свежей разнарядке сразу влияли на список ТС; дневной GPS-кэш остаётся действующим.

Excel содержит пять листов: **«Рейтинг ТС»**, **«По дням»**, **«Превышения скорости»**, **«ТОП-10»**, **«Методика»**. На основном листе «Рейтинг ТС» — **25 столбцов**: первая колонка «№ строки» всегда заполнена; «Место в рейтинге» находится в колонке 24, «Средний пробег вне Аккую за рабочий день, км (без норматива)» — в колонке 25. По запросу пользователя из этого листа убраны «Статус оценки» и «Норматив внутри Аккую по текущей модели»; сами данные остаются в расчётах/API, статус оценки по-прежнему виден на листе «ТОП-10», а норматив применяется для подсветки среднего внутреннего пробега.

На основном листе переименованы показатели среднего внутреннего пробега (колонка 9), среднего времени движения (13), среднего времени офисных стоянок (15), доли движения (16), количества превышений скорости внутри и вне Аккую (20–21) и штрафных баллов (22). Короткие заголовки «км/день» и «за день» по-прежнему означают **среднее за плановый рабочий будний день по разнарядке**. Заголовок колонки 16 «В движении на территории АККУЮ, %» означает именно долю времени движения **среди суммы движения внутри Аккую и стоянок в выбранных офисных зонах**, а не процент от полного времени нахождения ТС на площадке. Колонка 12 показывает долю пробега **вне Аккую от общего пробега, %**, а колонка 13 — среднее время движения, а не сумму за период. Фактическое время движения за каждый день осталось на листе «По дням».

Все пять колонок времени движения и офисных стоянок на листах «Рейтинг ТС» (13–15) и «По дням» (10–11) выгружаются как **числовая длительность Excel** с форматом `[hh]:mm`: 125 минут отображаются `02:05`, а 1565 минут — `26:05` (без сброса после суток). Н/Д остаётся пустой ячейкой. В «Превышениях скорости» начало и окончание событий — полноценные ячейки даты/времени с показом `дд.мм.гггг чч:мм` по Стамбулу; длительность коротких превышений сохраняется в секундах для точности. Формат JSON API и веб-портала не меняется. Лист «ТОП-10» содержит оба списка с госномерами, моделями, итоговыми баллами и статусами оценки. Средний пробег внутри Аккую сравнивается с нормативом Transit/прочих моделей и подсвечивается; суммарный и средний внешний пробег не окрашиваются по дневному порогу. Лист «Методика» содержит объяснения расчётов и подсветки. Подтверждённые нарушения выделяются цветом. Текстовые данные из разнарядок и геозон сохраняются как строки Excel, даже если начинаются со знака формулы `=`. HTML-таблица по-прежнему содержит обе доли пробега и долю движения в сумме движения и офисных стоянок.

## Приёмка перед публикацией

```bash
python verify_all.py --static
python verify_all.py --runtime
```

После независимого ревью желательно проверить на read-only staging с реальными GPS за 1, 7 и 30 суток: длительность выполнения, совпадение количества машин с разнарядкой, непротиворечивость пробегов и отсутствие событий скорости внутри тоннелей. Публикация на основной сервер производится **отдельным согласованным релизом**, с проверкой нагрузки и возможностью отката.
